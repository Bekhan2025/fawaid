# «аль-Фаваид» — многослойная читалка

Интерактивная среда чтения книги Ибн Каййима аль-Джаузиййи **«аль-Фаваид»** (الفوائد, «Пользы»)
по русскому изданию (М.: Умма, 2013, 480 с.).

Идея проста: классический текст — это один смысловой блок, который можно показать тремя
способами. Читатель переключает слои в шапке и смотрит на ту же запись так, как ему удобно
сейчас: читать как книгу, разобрать аргументацию или увидеть структуру глазами.

## Три слоя одной записи

| Слой | Что это | Оформление |
|---|---|---|
| **Книга** | Полный текст издания «Умма, 2013» по записям оглавления, со всеми сносками | Минималистичный «книжный» вид: сплошной текст, абзацы, без декора |
| **Разбор** | Структурированные тезисы: ключевая мысль, логика аргументации, списки | Сжатая подача для быстрого понимания |
| **Атлас** | Визуальные примитивы: формы по содержанию записи: карты последствий, причинные связи, шкалы и карточки | Схемы и диаграммы |

Записи, для которых разбор ещё не подготовлен, показывают сообщение о состоянии слоя и предлагают
остаться в слое «Книга» — так книга полностью читаема с первого дня, а слои наполняются
постепенно, по одной записи.

## Что уже сделано

- **Полный текст книги**: все 136 записей оглавления издания, извлечённых из PDF
  издания, распределены по 12 тематическим частям навигации;
  сноски издания сохранены и восстановлены в тексте.
- **Навигация по книге**: сайдбар «части → записи», порядок чтения по страницам издания,
  переходы «предыдущая/следующая», листание стрелками ← / →, прогресс чтения.
- **Эталонная запись e310 «Золотая середина»**: все три слоя готовы — мини-шкала,
  таблица пяти качеств × пяти зон с синхронной hover-подсветкой, современные примеры,
  практика из трёх шагов.
- **Запись e309 «Цена удовлетворения страсти»**: разбор по тексту с. 309, сравнение
  двух тягот, карта всех перечисленных последствий и связь «деяния → качества».
- **e12 и e299**: условия получения пользы от Корана и причинные связи лжи;
  сопоставления и схемы следуют содержанию, цитаты раскрываются из исходного текста
  с переходом к абзацу в книге.
- **e187**: цели и обстоятельства упования, условные ветви использования причин.
- **Удобство чтения**: переход к сноске и обратно, закладки на абзацы, сохранённые
  размер текста и межстрочный интервал.
- **Поиск**: заголовки, абзацы, сноски и словарь; переход к найденному фрагменту.
- **Словарь терминов**: инлайн-бейджи `[[term:id]]` открывают всплывающие карточки
  с арабским написанием (шрифт Amiri), транслитерацией и пояснением.
- **Темы**: светлая «бумага/чернила» и тёмная, переключатель в шапке.
- **Мобильная версия**: сворачиваемый сайдбар, нижнее меню, компактная шапка.

## Архитектура данных

```
BookData
├── meta          — книга и автор (рус/араб)
├── terms         — словарь терминов для бейджей [[term:id]]
├── parts         — навигация: 12 тематических частей → 136 записей оглавления (TOC_PARTS)
└── chapters      — готовые главы «Разбор/Атлас» (ch1 «Золотая середина», ch2 «Цена удовлетворения страсти»)
```

Ключевые типы в `src/lib/types.ts`:

- `BookTextEntry` — запись издания: маркер («Польза», «Раздел», «Правило»…), заголовок,
  страницы, абзацы `BookPara[]`, сноски. Полный текст книги живёт в
  `src/content/book-text/p*.json` и собирается в `BOOK_TEXT` (`src/content/book.ts`).
- `BookPara` — строка (обычный абзац), `{ verse: string[] }` (стихотворная цитата)
  или `{ center: string }` (центрированный текст, басмала); `{{n}}` — маркер сноски.
- `Chapter` → `Section[]` — готовый разбор: каждый секции может иметь слои `book`,
  `razbor` и `atlas` (виды примитивов: `mini`, `spectrum`, `examples`, `steps`, `cards`, `chain`).
- Источник привязок записи к главе — `src/content/chapter-links.json` (`entryId → chapterId`).
  Привязки применяются в памяти; исходные книжные файлы остаются неизменными.

Инлайн-разметка текстов: `**жирный**` — ключевая мысль, `[[term:id]]` — термин-бейдж,
`{{n}}` — сноска.

## Работа с контентом

Текст книги в `src/content/book-text/p*.json` и оглавление `src/content/toc.ts`
зафиксированы: их нельзя редактировать, форматировать или регенерировать.
PDF и каталог `upload/` для дальнейшей работы не нужны. Скрипты извлечения
сохранены только как исторические инструменты и не запускаются.

Для новых Разборов и Атласов используйте проектный скилл
[`.agents/skills/fawaid-editorial/SKILL.md`](.agents/skills/fawaid-editorial/SKILL.md).
Привязки из `src/content/chapter-links.json` применяются при сборке данных приложения,
без изменений в книжных JSON и оглавлении. Проверка: `bun run validate:content`.

## Ссылки и продолжение чтения

Ссылка `/?entry=e310&layer=atlas` открывает конкретную запись и слой (`book`, `razbor`, `atlas`).
Переходы по записям и слоям попадают в историю браузера; «Назад/Вперёд» возвращают
также позицию прокрутки. Последние запись, слой и относительная позиция сохраняются
в `localStorage` этого браузера. При открытии без параметров чтение продолжается
с сохранённого места, а явная ссылка имеет приоритет над сохранёнными записью и слоем.
Для той же записи и слоя после перезагрузки восстанавливается позиция.
Поиск и закладки добавляют к ссылке якорь `#e309-para-0` для точного абзаца.
Индекс поиска строится при открытии панели, не переписывает текст издания;
поиск не учитывает регистр и различие е/ё, все слова запроса должны встретиться
в одном фрагменте. Результаты выводятся порциями по 30, с общим числом совпадений.

Некорректная ссылка открывает `e310` в слое «Книга»; неизвестный слой заменяется на `book`.
Если браузер запрещает локальное хранение, навигация и история продолжают работать.

## Стек

- **Next.js 16** (App Router) + **React 19**
- **Tailwind CSS 4**, **shadcn/ui**, Radix Primitives (Tabs, Popover, Sidebar…)
- Шрифты: Manrope (интерфейс), Playfair Display (заголовки книги), Amiri (арабский)
- Пакетный менеджер и рантайм — **Bun**
- Контент — статические TS/JSON, без базы данных и внешних сервисов

## Команды

```bash
bun install          # установка зависимостей
bun run dev          # dev-сервер на http://localhost:3000
bun run lint         # ESLint
bun run typecheck    # TypeScript
bun run validate:content # связи и целостность контента
bun run test:content # проверки валидатора на повреждённых данных
bun run check        # lint, TypeScript, контент и тесты
bun run build        # production-сборка (standalone)
bun run start        # запуск собранного сервера
```

## Проверка перед публикацией

```bash
bun install --frozen-lockfile
bunx playwright install chromium
bun run release:check
```

Команда выполняет lint, TypeScript, проверки контента и тесты поиска/валидатора,
затем production-сборку, отчёт о размере JS и браузерные тесты на 1280 и 390 px.
Для сборки нужен доступ к Google Fonts; на чистом Linux могут понадобиться системные
зависимости Chromium (`bunx playwright install --with-deps chromium`).
Тесты сами запускают собранный сервер на `127.0.0.1:3100`; этот порт должен быть свободен.
Остановите dev-сервер перед production-сборкой: они используют общий каталог `.next`.

Покрываются прямые ссылки, история, восстановление позиции, сноски, закладки,
типографика, поиск, темы, подготовленные атласы, hover и недоступное локальное
хранение. Скриншоты обеих тем сохраняются в `test-results/`; при сбое сохраняется
Playwright trace. Отчёт `.next/bundle-report.json` показывает суммарный размер всех
JS-чанков (включая отложенные), gzip и самые крупные файлы; это не размер первого
запроса страницы. Выполнение команды не публикует проект.

## Принципы контента

1. **Ничего не выдумывать.** Авторский текст в слое «Книга» — только из издания.
   Толкования, пересказ и современные примеры — в слоях «Разбор» и «Атлас».
2. **Дополнения составителя видны.** Секции и вставки, которых нет у автора,
   помечаются (`additionOnly`, пунктирная рамка).
3. **Читаемость прежде красоты.** Слой «Книга» намеренно минималистичен: оформление
   не должно конкурировать с текстом.
4. **По одной записи.** Слои «Разбор» и «Атлас» наполняются записями по очереди,
   от самых востребованных.

## GitHub Pages

Публикация: https://bekhan2025.github.io/fawaid/
Репозиторий: https://github.com/Bekhan2025/fawaid

В настройках репозитория откройте **Settings → Pages → Build and deployment →
Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` запускается
при push в `main` и вручную из Actions; pull request проходит проверки без публикации.
Дополнительные токены и секреты для workflow не нужны: используется `GITHUB_TOKEN`.

Перед публикацией выполняются проверки кода и контента, статическая сборка и
браузерные тесты для компьютера и телефона. GitHub Pages получает только каталог `out/`.
После успешного workflow изменения в `main` публикуются автоматически.

Проверить такой же вариант локально:

```bash
bun run check
bun run build:pages
bun run test:pages
bun run preview:pages  # http://127.0.0.1:3000/fawaid/
```

Сборка Pages использует `output: export` и `NEXT_PUBLIC_BASE_PATH=/fawaid`.
Обычные `bun run dev`, `bun run build` и `bun run start` сохраняют локальный запуск
в корне сайта. При переименовании репозитория нужно обновить префикс в командах
`build:pages`, `preview:pages`, `test:pages` в `package.json`.
